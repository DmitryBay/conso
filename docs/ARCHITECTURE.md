# Hotel Concierge MVP — архитектура

## 1. Границы продукта

Приложение строится как модульный Laravel-монолит с общей доменной моделью и тремя независимыми интерфейсами:

| Контур | URL MVP | Пользователи | Назначение |
| --- | --- | --- | --- |
| Platform | `/platform` | Super admin | Компании, владельцы, тарифы, состояние аккаунтов |
| Workspace | `/workspace` | Владелец, менеджер | Канбан заявок, сотрудники, дерево услуг, уведомления |
| Guest | `/guest/{hotel}` | Гость | Каталог, отдельные заявки на услуги, общий счёт, статусы |

Каждый контур получает собственный layout и навигацию, но использует общие сервисы и API. Позже Workspace и Guest можно упаковать в native shell/WebView или заменить native-клиентом, не меняя серверную бизнес-логику.

## 2. Роли и изоляция данных

- `super_admin` не привязан к компании и работает только в Platform.
- `company_owner` привязан к одной компании, управляет своей командой и настройками.
- `manager` привязан к одной компании, работает только с заявками и услугами своей компании.
- `guest` связан с компанией и номером через ограниченную гостевую сессию/QR-токен.

Все tenant-таблицы содержат `company_id`. Доступ ограничивается двумя слоями: middleware выбирает активную компанию, а Policies/queries всегда фильтруют записи по `company_id`. Идентификатор компании никогда не принимается от клиента как источник истины.

## 3. Основная модель данных

```text
Company
 ├── Users (owner, managers)
 ├── Properties / Rooms / GuestSessions
 ├── ServiceCategories (parent_id — дерево)
 │    └── Services (price, availability, SLA)
 └── Requests
      ├── RequestItems
      ├── RequestStatusHistory
      ├── Comments
      └── Assignments
```

Реализованы `Company`, `User`, `Room`, `GuestSession`, единое дерево `ServiceNode`, заявки `ServiceRequest`, позиции `ServiceRequestItem`, история статусов и database-уведомления. Гостевая сессия ограничена компанией, активным номером и сроком действия; PIN хранится только как хеш.

Стартовый шаблон `ServiceCatalogSeeder` создаёт редактируемое дерево из трёх уровней: главная категория → дополнительный выбор → услуга. Демо-каталог содержит 6 главных категорий, 15 подкатегорий и 47 услуг. Повторный запуск шаблона идемпотентен и не создаёт дубликаты; существующие связанные заявки сохраняют ссылки на услуги.

## 4. Статусы и real-time

Базовый поток заявки: `new → accepted → in_progress → waiting_guest → completed`, отдельно `cancelled`. Каждое изменение пишется в историю.

События публикуются через Laravel Broadcasting. В production драйвером может быть Pusher; для self-hosted варианта — Laravel Reverb. Интерфейс подписывается на приватный канал `company.{id}`. Проверка принадлежности пользователя компании обязательна при авторизации канала.

## 5. API и мобильная готовность

- Web использует обычные Laravel controllers на первом этапе.
- Мобильные клиенты получают версионированный `/api/v1`.
- Для owner/manager — Sanctum personal/device tokens.
- Для гостя — короткоживущая room session после QR/PIN, без постоянного пароля.
- Деньги хранятся целым числом в minor units, базовая валюта — ISO 4217 на уровне компании. Для гостя отображается приблизительный USD-эквивалент по централизованному конфигурационному курсу.
- Интерфейсы Guest и Workspace локализованы на `ru`, `uk`, `id`, `en`, `ar`, `he`, `zh`, `ko`; арабская и ивритская версии используют RTL. Язык гостя и язык менеджера сохраняются независимо.
- Все даты хранятся в UTC, показываются в timezone компании.

## 6. Порядок реализации

1. **Platform — готово:** super admin, компании, назначение владельца и статусы.
2. **Workspace — готово:** дерево услуг, команда, канбан заявок, история, database-уведомления и приватные Broadcasting-события.
3. **Guest — готово:** PIN-сессия номера, отдельная заявка на каждую услугу, общий счёт за сессию, платные/бесплатные позиции, мультиязычность и отслеживание.

## 7. Production-контур

Laravel 13, PHP 8.3+, MySQL 8, Redis для cache/queue, Horizon для очередей, Pusher/Reverb для событий, S3-compatible storage для фото услуг. Bootstrap 5 используется как единая адаптивная UI-база.
